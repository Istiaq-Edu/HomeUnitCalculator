# 2026-11-07

## Room removal feature (Room Calculations section)
- Added per-card X remove button + header "Remove Room ▾" menu that lists every room number; both call `MainTab.remove_room(index)`.
- Deleting a middle room renumbers the rest sequentially, syncs `num_rooms_spinbox` (signals blocked), and offers a non-blocking InfoBar Undo (token-guarded so stale toasts cannot undo a newer deletion).
- `update_room_inputs(room_data=None)` is now data-driven: it snapshots/restores all room fields via `_snapshot_room_data()`. Fixing the old behaviour where changing room count wiped every room's data. Default-style names ("Room N") are dropped from snapshots so they follow position; custom names (e.g. "Flat C") are preserved.
- Renumbering is intentional: all save paths (PDF/CSV/Supabase) generate `Room {i+1}` from list position.
- No Supabase schema/SQL changes needed: `save_room_calculations()` replaces all rows for the month, `room_data` is JSONB, no ordinal column.
- Added `.order("id")` to `supabase_manager.get_room_calculations()` for deterministic reload order (bulk fetch already had it).
- Caveat: dashboard/local cache key monthly series by `room_name` string, so after renumbering historical "Room 10" and new "Room 10" refer to different physical rooms. Stable room identity across months would need a schema + code change.
- Tests: `tests/test_ui_room_removal.py` (14 tests). Note `tests/` is gitignored in this repo. Full suite: 157 passed (Python 3.12 at `C:\Program Files\Python312\python.exe`; default `python` is WorkBuddy 3.13 without PyQt5/qfluentwidgets).

## Review pass (same day) — regressions found and fixed
Preserving room data on rebuild exposed several loaders that relied on the old full wipe:
- `load_room_data_from_supabase_rows`: added `_reset_room_result_labels()` so Add Month no longer shows the previous month's calculated totals.
- `load_info_to_inputs_from_csv`: call `clear_room_inputs()` before filling (drops stale custom titles + `supabase_id`), and reset to one empty room when no room rows.
- `add_month_manager.load_next_month_to_ui` else branch: reset to one empty room.
- `load_info_to_inputs_from_supabase`: added else branch for months with no room records.
- Undo validity now compares only editable fields (`_editable_state`), not derived labels, so a recalculation after removal doesn't kill Undo; Undo rebuilds from the current state to avoid rolling back recalculated totals.
- `_invalidate_room_undo()` is called on every load/clear/user spinbox change; retires stale toasts and bumps the token.
- Menu actions defer via `QTimer.singleShot(0, ...)` and resolve the room by widget identity (avoids deleting the emitting QAction / removing the wrong room).
- `undo_button.show()` + `bar.adjustSize()` after `bar.addWidget()` since the InfoBar factory already showed the parent.
